## 2. What changed (`src/turab/auth/contract.py`)

**One function, `_value_problems`, for the loader and the judge alike.**
- The loader (`_schema_problems`) applies it to every node, the referenced
  frozen components included.
- `body_violations` applies it to every node it judges, and refuses with
  `ContractError`. It never reads a value of the wrong structure as
  something else.
- The two cannot diverge on what is well-formed.

| Keyword | The rule now | JSON Schema 2020-12 | This rule against it |
|---|---|---|---|
| `type` | a type name, or a **non-empty** list of distinct names, each a JSON type | Validation §6.1.1: a string or an array of unique strings | **stricter:** an empty list would admit nothing |
| `enum` | a **non-empty** list of **distinct** JSON values | §6.1.2: MUST be an array; SHOULD be non-empty; elements SHOULD be unique | the two SHOULDs made MUSTs |
| `const`, `default` | a JSON value | §6.1.3: any type; §9.2: no restriction | ours: a YAML date or a non-finite number is not JSON |
| `required` | a list of distinct strings | §6.5.3: an array; elements strings, unique | equal |
| `minimum` | a finite number, not a boolean | §6.2.4: MUST be a number | equal (JSON has no NaN or infinity) |
| `properties` | a mapping of string names to schemas | Core §10.3.2.1: an object; each value a schema | equal |
| `anyOf` | a non-empty list of schemas | Core §10.2.1.2: a non-empty array of schemas | equal |
| `allOf` (judge) | a non-empty list of schemas | Core §10.2.1.1: the same | equal |
| `additionalProperties` | `true` or `false` only; in an entry's own branch, `false` only | Core: any schema | **narrower:** a schema there is not read by the judge, so refused |
| `if` / `then` | together, or neither | Core §10.2.2: either alone is ignored | **stricter:** refused rather than silently ignored |
| `format` | a string, and `uuid` only | Validation §7 | §3 below |
| `$ref` (judge) | to an existing frozen component | — | `ContractError`, no longer `KeyError` |

**The messages** name the keyword, never a value of the body (the earlier
test, unchanged).

## 3. `date-time`: not admitted

**The choice:** the review's second option.
- `date-time` is no longer in `_ALL_OF_FORMATS`, so it is refused in an
  entry's branch **and** in any frozen component a branch refers to.
- `_format_holds` checks `uuid` only.
- The judge refuses to judge `date-time` (`ContractError`).

**Why:**
- JSON Schema's `date-time` is RFC 3339's `date-time` ABNF rule (Validation
  §7.3.1, referring to RFC 3339 §5.6).
- The judge used `datetime.fromisoformat`. **Measured on the project's Python
  (3.12.3)** (`evidence/PREP-ADD-ALL-OF-ADDENDUM-DATETIME.txt`), it accepts
  at least five strings that rule rejects:
  - a date alone;
  - a time without an offset;
  - the basic format;
  - an ISO week date;
  - a time without minutes.
- CORRECTION-009 carries no `date-time`; it refers only to `RequestCriterion`,
  which carries none.

**Its consequence, stated:** a future correction that narrows a field with a
`date-time`, or refers to a component carrying one (42 occurrences in the
frozen components), is refused at load until a checker held to RFC 3339 is
added and tested.
