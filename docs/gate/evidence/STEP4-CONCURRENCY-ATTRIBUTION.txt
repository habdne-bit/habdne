=== reading ===
M4 (lock removed): the pass WAITED for the locked row and did NOT write it;
  the concurrent value survived. The shipped test fails only on waited=True,
  i.e. because the no-wait skip is gone. What protected the value was the
  OUTER re-asserted predicate, re-evaluated after the wait (PostgreSQL 16,
  §13.2.1). This is the attribution the earlier harness could not show: there
  the same mutation failed by TIMEOUT.
M4 + outer predicate removed: the pass waited, WROTE the row, and the
  concurrent reconfirmation was overwritten to NEEDS_CONFIRMATION — the lost
  update both guards exist to prevent.
Outer predicate removed, lock kept: passes. SKIP LOCKED alone protects; the
  outer predicate is redundant while the lock is present, and a guard when it
  is not (previous two runs).
The same five variants run on every suite run as
test_which_mechanism_protects_a_concurrent_reconfirmation; their facts are
recorded per case as JUnit properties in junit-run.xml.
