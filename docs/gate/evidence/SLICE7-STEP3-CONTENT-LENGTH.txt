Reading:
  * httptools (the default parser of uvicorn[standard]): '9' x 5000 is
    refused by the parser itself, before the application. '0' x 5000 + '2'
    (a 2-byte body, declared with leading zeros) PASSES the parser, reaches
    _read_limited, and int(declared) raises ValueError: the answer is the
    generic 500 INTERNAL_ERROR, not the decided 400, and no webhook access
    record is written (the generic handler answers). '0' x 4299 + '2' (4300
    digits) converts, and is read normally.
  * h11: refuses all three long values itself ("Invalid HTTP request
    received"); none reaches the application.
  * A non-ASCII digit (byte 0xB2, Latin-1 '²', which str.isdigit accepts and
    int refuses): refused by both parsers; it does not reach the route
    through these servers. The fix does not rely on that.
  * Nothing was written: webhook_events held the same rows before and after.

The fix (see the delivery note): `declared_over_limit` accepts ASCII decimal
only, drops leading zeros, and decides "over" by the count of significant
digits before any int(), which then converts at most six digits.
